At a glance

The table gives the mean change from the 16-bit run of the same model. A cell is one model with a 16-bit run it can be compared with.

In the table headings, ↑ means a higher value is better and ↓ a lower value is better. A column with no arrow has no better direction.

Metrics

The verifier is the same model asked, for each of its own sampled solutions, whether the solution is correct. Each judgement is compared with whether the answer really is correct.

Safety risk: false positive rate (FPR)

Lower is better.

$\frac{FP}{FP+TN}$

How often the verifier approves a flawed trace. A rise as precision drops means the model is becoming falsely confident, which would pollute a self-training set.

Discrimination: MCC

Higher is better.

$\frac{TP\cdot TN-FP\cdot FN}{\sqrt{(TP+FP)(TP+FN)(TN+FP)(TN+FN)}}$

A balanced quality measure that is robust to class imbalance. Zero means the verdicts say nothing about correctness.

Selection utility: guided minus voted

Higher is better, with a caveat.

$Acc_{guided} - Acc_{voted}$

Whether voting among approved traces beats plain voting. The baseline moves when the generator is quantized, so a gain can come from a weaker generator rather than a better verifier. Read it together with FPR and MCC.

Results by dataset

Changes are against 16-bit with a 95% paired bootstrap interval over questions. Green or red means the interval excludes zero; for FPR a rise is red, for MCC a fall is red.

How these numbers are made

  • All precisions of a model are scored on the same questions: the first ones, in run order, for which every precision holds all its solutions. Every row therefore has the same number of traces, and a run with too few complete questions is left out.
  • Each trace is relabelled from its stored solution text with the current extractor, and the verdict is parsed again with the shared strict parser.
  • A solution cut off at the token limit is kept. As on the Phase 1 page it counts as wrong and does not vote, so an approval of it is a false positive. Most cut-off solutions are rejected, which lowers the false positive rate where many are cut off: read that rate next to the Cut off column, and compare it within a model, not between models.
  • Traces with no verdict are counted in No verdict and left out of the rates.
  • Cut-off solutions can only be identified while the generator run that produced them still exists. Where it was replaced the column says unknown, the row is scored from the solution text alone, and its precisions are not compared.
  • A verifier that approves almost every trace has an FPR near 100% and an MCC near zero whatever its precision. The notes column marks those rows.
