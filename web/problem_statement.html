The core problem

Summary

This project investigates a gap in on-device AI: does quantization destroy a small model's ability to evaluate its own reasoning? We use GSM8K as the primary benchmark because it has a useful difficulty curve (about 60% base accuracy), which lets us measure the effect of a verifier without hitting a ceiling.

The context. Large language models can "teach themselves" by generating answers, judging which ones are good, and training on those. This works because judging an answer is usually easier than generating one from scratch.

The conflict. Two things are true at once:

  1. Small models are worse at judging their own answers than large ones.
  2. Deployed models are almost always quantized (shrunk to 8-bit or 4-bit) to run on-device.

The research question. Nobody appears to have studied what happens when you combine these two things. Does shrinking a model make its self-judgment worse, better, or unaffected? Can a quantized model reliably critique itself?

The core hypothesis: can a quantized model run the verifier phase reliably without polluting its own training data?

The datasets

GSM8K (grade-school math)

Type: mathematical reasoning, open-ended.

Status: primary benchmark. It needs rigid, step-by-step logic, so it is sensitive to heavy quantization. Its difficulty (about 60% base accuracy for 1B models) leaves the verifier room to improve the outcome.

SVAMP and CommonsenseQA

SVAMP: dropped. Models hit a ceiling (about 85% base accuracy), leaving almost no incorrect examples for the verifier to learn from.

CommonsenseQA: de-prioritised. In multiple choice, extra generation diversity raises the chance of guessing the right letter, which skews the metrics.
